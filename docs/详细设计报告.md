## 1. 引言

## 2. 系统概述

### 2.1 系统目标

本系统旨在为高校学生提供一个基于微信生态的校内二手商品交易平台，核心目标如下：

1. **便捷性**：依托微信小程序，无需安装 App，扫码即用，流量入口低摩擦。
2. **可信性**：通过微信实名体系、商品审核机制与信誉评分制度保障交易可信度。
3. **安全性**：所有通信使用 HTTPS，通过 JWT 双 Token 机制管理用户会话，防范身份伪造与越权操作。
4. **可管理性**：内置管理后台，支持商品审核、用户管理、举报处理与数据统计。

### 2.2 系统功能概览

系统按用户角色划分为以下功能域：

**普通用户**
- 微信一键登录与账号管理
- 商品浏览（首页推荐、分类筛选、关键词搜索、排序）
- 商品发布与管理（草稿、待审、已发布、下架）
- 交易流程（下单→卖家确认→交易完成→评价）
- 收藏管理与浏览历史
- 举报与申诉功能
- 个人信誉分查看

**管理员**
- 商品审核（通过/拒绝）
- 用户封禁/解封
- 举报单处理
- 平台数据统计（用户增长、商品分布、交易量、举报趋势）
- 操作日志查看

### 4.2 本地存储管理模块（utils/storage.js）

本模块统一封装所有涉及 `wx.setStorageSync` / `wx.getStorageSync` 的操作，是前端认证状态的核心管理器。

#### 4.2.1 存储键名常量（来自 utils/constants.js）

| 键名 | 存储内容 |
|------|----------|
| `access_token` | JWT Access Token 字符串 |
| `refresh_token` | JWT Refresh Token 字符串 |
| `token_expires_at` | Access Token 到期时间戳（ms） |
| `user_info` | 当前登录用户信息 JSON 对象 |

#### 4.2.2 关键函数设计

| 函数 | 功能描述 |
|------|----------|
| `saveAuth(accessToken, refreshToken, expiresIn, userInfo)` | 一次性保存所有认证信息，计算 `expires_at = now + expiresIn * 1000` |
| `clearAuth()` | 清除所有认证相关存储，用于登出操作 |
| `getAccessToken()` | 读取当前 Access Token |
| `getRefreshToken()` | 读取当前 Refresh Token |
| `isLoggedIn()` | 判断是否有 Access Token 存在（不校验有效性） |
| `isTokenExpired()` | 判断 Access Token 是否过期，**提前 60 秒**返回 `true`，留出刷新缓冲窗口 |
| `getUserInfo()` | 读取缓存的用户信息对象 |

**令牌过期提前检测设计**：
```javascript
isTokenExpired() {
  const expiresAt = wx.getStorageSync('token_expires_at')
  if (!expiresAt) return true
  return Date.now() > expiresAt - 60000  // 提前 60 秒判为过期
}
```

此设计可有效避免在 Token 边界时刻因网络延迟导致 401 错误，提升用户体验。

### 4.3 HTTP 请求封装（utils/api.js）

对 `wx.request` 进行统一封装，处理以下横切关注点：

1. **Base URL 注入**：自动拼接后端服务地址前缀。
2. **Authorization 头注入**：每次请求自动读取 Storage 中的 Access Token，拼装 `Bearer <token>` 头。
3. **Token 刷新逻辑**：请求发起前调用 `isTokenExpired()` 检查，如已过期则先调用 `POST /api/auth/refresh` 获取新 Token，再重试原始请求。
4. **错误归一化**：将 `wx.request` 的 `fail` 回调（网络错误）和 HTTP 4xx/5xx 状态码统一转换为 rejected Promise，供上层捕获。

### 4.4 自定义 TabBar 组件（custom-tab-bar）

#### 4.4.1 设计动机

微信小程序原生 TabBar 的 `selectedIndex` 仅在页面跳转时自动同步，在以下场景会失去同步：
- 通过 `wx.navigateTo` 跳转后 `wx.navigateBack` 返回
- 登录态变化后需要动态控制 TabBar 样式

#### 4.4.2 实现方案

自定义 TabBar 组件暴露 `setData` 接口，由各 TabBar 页面在 **`onShow` 生命周期**主动调用同步：

```javascript
// pages/home/index.js
onShow() {
  const tabBar = this.getTabBar()
  if (tabBar) {
    tabBar.setData({ selected: 0 })  // 首页 index=0
  }
}
```

**三个 TabBar 页面与 index 对应关系**：

| 页面 | selected 值 | 图标/文字 |
|------|-------------|-----------|
| `pages/home/index` | 0 | 首页 |
| `pages/post/index` | 1 | 发布 |
| `pages/user/index` | 2 | 我的 |

#### 4.4.3 选中状态样式

```javascript
// custom-tab-bar/index.js
data: {
  selected: 0,
  list: [
    { pagePath: 'pages/home/index',  text: '首页', icon: '...' },
    { pagePath: 'pages/post/index',  text: '发布', icon: '...' },
    { pagePath: 'pages/user/index',  text: '我的', icon: '...' }
  ]
}
```

WXSS 中通过 `selected === index` 条件绑定激活色，与页面 `onShow` 主动同步配合，保证任何跳转路径下颜色状态均正确。

### 4.5 首页模块（pages/home）

#### 4.5.1 数据加载策略

首页同时展示「推荐商品」与「最新商品」两个列表，采用 `Promise.allSettled` 并发加载，避免串行等待：

```javascript
onLoad() {
  this.setData({ skeletonVisible: true })
  const startTime = Date.now()
  
  Promise.allSettled([
    this.loadRecommended(),
    this.loadLatest()
  ]).then(() => {
    // 骨架屏最小可见时长 800ms，避免闪烁
    const elapsed = Date.now() - startTime
    const delay = Math.max(0, 800 - elapsed)
    setTimeout(() => {
      this.setData({ skeletonVisible: false })
    }, delay)
  })
}
```

**骨架屏最小可见时长（800ms）**的设计目的：当网络极快时（如本地开发），骨架屏在瞬间消失会产生闪烁感，固定至少展示 800ms 可提升视觉平滑度。

#### 4.5.2 下拉刷新

`onPullDownRefresh` 触发后重置分页状态并重新并发加载，加载完成后调用 `wx.stopPullDownRefresh()`。

### 4.7 发布商品页（pages/post）

#### 4.7.1 表单校验规则

| 字段 | 校验规则 |
|------|----------|
| 标题 | 非空，2~50 字符 |
| 价格 | 非空，正数，最多两位小数 |

#### 4.7.2 图片上传流程

```
用户点击"添加图片"
    ↓
wx.chooseMedia({ count: 9 - currentImages.length, mediaType: ['image'] })
    ↓
遍历 tempFilePaths，调用 wx.uploadFile({ url: '/api/products/{id}/images', ... })
    ↓
上传成功 → 服务器返回图片 URL → 追加至本地 images 数组 → setData 触发视图更新
```

图片计数动态控制：每次添加时，`count` 参数设置为 `9 - 当前图片数量`，防止超出上限。

### 4.8 个人中心页（pages/user）

#### 4.8.1 信誉分颜色分级

```javascript
// utils/constants.js 中定义的映射
SCORE_LEVELS: [
  { min: 90, color: '#07c160', label: '信誉良好' },   // 绿色
  { min: 60, color: '#fa8c16', label: '信誉一般' },   // 橙色
  { min: 0,  color: '#f5222d', label: '信誉较差' }    // 红色

```

渲染时遍历 `SCORE_LEVELS`，取第一个满足 `score >= min` 的项作为展示颜色，与服务端 `users.score` 字段（默认 100，可因差评扣减）实时对应。

#### 4.8.2 登出流程

```

    ↓ 确认

    ↓
clearAuth()（清除本地所有 Token 和用户信息）
    ↓
app.globalData.userInfo = null
    ↓
wx.reLaunch({ url: 'pages/home/index' })（强制返回首页并清栈）
```

### 5.5 认证模块（api/routers/auth.py）

#### 5.5.1 微信登录流程

```
前端: wx.login() → 获取临时 code
    ↓ POST /api/auth/wx-login { code }
后端: 携带 code + AppID + AppSecret
    → 请求微信 jscode2session 接口
    → 获取 openid + session_key
    ↓
生成用户唯一 ID:
    user_id = int(sha256(openid.encode()).hexdigest()[:8], 16)
    ↓
查询数据库 users 表（以 openid 为 key）
    → 不存在则自动注册（首次登录）
    → 已存在则直接登录
    ↓
签发 Access Token（HS256，1小时有效期）
签发 Refresh Token（HS256，7天有效期，存入 refresh_tokens 表）
    ↓
返回 { accessToken, refreshToken, expiresIn, userInfo }
```

**用户 ID 生成算法说明**：
```python
user_id = int(hashlib.sha256(openid.encode()).hexdigest()[:8], 16)
```
取 SHA-256 哈希值的前 8 位十六进制字符转换为整数，生成数值型用户 ID。此方案满足：openid 不出现在数据库索引中（保护用户隐私），ID 确定性可复现（同一 openid 始终生成同一 ID）。实际表设计中 `users.id` 使用此生成值作为主键（非 AUTO_INCREMENT）。

#### 5.5.2 Token 刷新流程

```
POST /api/auth/refresh { refreshToken }
    ↓
验证 refreshToken 签名及有效期（PyJWT decode）
    ↓
查询 refresh_tokens 表：验证 revoked=0 且未超期
    ↓
签发新 Access Token（重置1小时有效期）
    ↓
返回 { accessToken, expiresIn }
```

Refresh Token 不轮换（单次使用后不作废），但支持显式登出时撤销（设置 `revoked=1`）。

#### 5.8.1 订单状态机

```
[创建]     [预定]      [确认]       [完成]
CREATED ──▶ RESERVED ──▶ CONFIRMED ──▶ COMPLETED
   │            │             │
   └────────────┴─────────────┘
                    │
                 CANCELLED
```

**状态流转规则**（`order_service.py` 中明确校验）：

| 操作 | 前置状态 | 目标状态 | 操作方 | 副作用 |
|------|----------|----------|--------|--------|
| 创建订单 | - | CREATED | 买家 | 无 |
| 卖家确认 | CREATED | RESERVED | 卖家 | 无 |
| 交易确认 | RESERVED | CONFIRMED | 买家 | 无 |
| 完成交易 | CONFIRMED | COMPLETED | 系统/买家 | 商品状态 → SOLD |
| 取消订单 | CREATED/RESERVED | CANCELLED | 买/卖家 | 无 |

**完成订单时的联动逻辑**：
```python
def complete_order(order_id: int) -> dict:
    order = get_order(order_id)
    if order["status"] == OrderStatus.COMPLETED.value:
        return {"id": order_id, "status": OrderStatus.COMPLETED.value}  # 幂等返回
    if order["status"] != OrderStatus.CONFIRMED.value:
        raise StateConflictError("order cannot be completed from current status", order)
    completed = order_crud.update_order_status(order_id, OrderStatus.COMPLETED)
    product_crud.update_product(order["productId"], {"status": ProductStatus.SOLD.value})
    return {"id": order_id, "status": completed["status"]}
```

**幂等设计**：重复调用 `complete_order` 时，若订单已是 COMPLETED 状态，直接返回当前状态，不抛出错误，确保接口幂等性。

## 6. 数据库设计

### 6.1 设计原则

1. **字符集**：全部使用 `utf8mb4`，支持 emoji 等四字节 Unicode 字符。
2. **存储引擎**：所有表使用 `InnoDB`，支持事务与外键。
3. **主键策略**：业务主键（`users.id`）由应用层生成（SHA-256 哈希），其他表使用 `AUTO_INCREMENT`。
4. **索引策略**：常用查询条件建立复合索引，避免全表扫描。
5. **时间字段**：统一使用 `DATETIME` 类型，`created_at` 默认 `CURRENT_TIMESTAMP`，`updated_at` 配合 `ON UPDATE CURRENT_TIMESTAMP` 自动维护。

### 6.2 实体关系概述

```
users ──┬── products (owner_id)
        ├── orders (buyer_id / seller_id)
        ├── reviews (reviewer_id / reviewee_id)
        ├── favorites (user_id)
        ├── reports (reporter_id / assignee_id)
        └── refresh_tokens (user_id)

products ──┬── product_images (product_id)
           ├── orders (product_id)
           ├── favorites (product_id)
           ├── reviews (product_id)
           └── categories (category_id)

orders ──── reviews (order_id)

reports ── (target_type, target_id) → polymorphic reference to products/users/orders
```

## 8. 安全设计

### 8.1 身份认证设计

#### 8.1.1 JWT 双 Token 机制

```
Access Token:
  - 有效期：1 小时（JWT_EXPIRES_SECONDS=3600）
  - 算法：HS256
  - Payload：{ user_id, exp, iat }
  - 存储：前端 Storage（内存级，不落 cookie）

Refresh Token:
  - 有效期：7 天（JWT_REFRESH_EXPIRES_SECONDS=604800）
  - 算法：HS256
  - 存储：前端 Storage + 后端 refresh_tokens 表（支持服务端撤销）
```

**安全考量**：
- Access Token 短期有效，降低泄露后的窗口期风险。
- Refresh Token 服务端持久化，支持主动撤销（登出、账号封禁）。
- 前端提前 60 秒检测过期并刷新，消除边界时刻的 401 错误。

#### 8.1.2 微信 openid 保护

openid 不作为用户 ID 直接使用，通过 SHA-256 哈希生成数值型 ID：

```python
user_id = int(hashlib.sha256(openid.encode()).hexdigest()[:8], 16)
```

此设计确保：
- 数据库中的用户 ID 无法逆推出 openid
- openid 仅在 `users.openid` 字段中以原始形式存储，不出现在任何日志或响应体

### 8.2 权限控制设计

#### 8.2.1 资源所有权校验

商品更新/删除、订单操作等接口，在业务层进行所有权校验：

#### 8.2.2 管理员权限隔离

管理后台接口（`/api/admin/**`）通过独立鉴权装饰器保护，与普通用户接口的权限校验逻辑完全隔离，防止横向越权。

### 8.3 数据传输安全

- 微信 AppSecret 通过 `.env` 文件管理，不硬编码在代码中，不提交至版本库（`.gitignore` 排除）。

## 9. 异常处理设计

### 9.1 业务异常类层次

```
Exception
└── BusinessError（基类）
    ├── http_status: int（HTTP 状态码）
    ├── biz_code: int（业务错误码）
    ├── message: str（错误描述）
    └── detail: any（上下文数据）
        ├── ResourceNotFoundError
        │     http_status=404, biz_code=4040
        └── StateConflictError
              http_status=409, biz_code=4090
```

### 9.2 全局异常处理

FastAPI 全局注册 `BusinessError` 处理器，将业务异常统一转换为标准 `api_error` 响应格式：

```python
@app.exception_handler(BusinessError)
async def business_error_handler(request, exc):
    return JSONResponse(
        status_code=exc.http_status,
        content=api_error(exc.biz_code, exc.message, exc.detail)
    )
```

前端可通过 `response.data.code !== 200` 统一判断业务错误，再根据具体 code 分支处理（如 4010 跳转登录页，4040 显示"商品不存在"）。

### 9.3 前端异常处理策略

| 错误类型 | 处理策略 |
|----------|----------|
| 网络错误（wx.request fail） | 弹出"网络异常，请检查连接"Toast |
| 401 Unauthorized | 尝试刷新 Token；刷新失败则跳转登录页 |
| 404 Not Found | 显示"内容不存在"并提供返回按钮 |
| 409 State Conflict | 提示具体冲突原因（如"商品已售出"） |
| 500 Server Error | 弹出"服务暂时不可用"Toast |

### 12.1 数据库索引策略

| 表 | 索引 | 优化场景 |

| products | `idx_products_status_created` | 首页最新商品列表（WHERE status='PUBLISHED' ORDER BY created_at） |
| products | `idx_products_category` | 分类筛选 |

| orders | `idx_orders_buyer/seller` | 用户订单列表查询 |
| reports | `idx_reports_target` | 按举报对象查询（多态引用联合索引） |
| refresh_tokens | `idx_refresh_tokens_expires` | 定期清理过期 Token |
| favorites | `uq_favorites_user_product` | 重复收藏判断（唯一约束即索引） |

### 12.2 前端性能优化

| 优化点 | 实现方式 |
|--------|----------|
| 首页并发加载 | `Promise.allSettled` 同时请求推荐和最新商品 |
| 骨架屏 | 最小展示 800ms，避免低延迟时的闪烁感 |
| 分页懒加载 | 触底事件触发下一页加载，`loadMore` 状态防重复请求 |
| 图片懒加载 | `<image lazy-load="true">` 属性，视口外图片延迟加载 |
| setData 最小化 | 仅传递变更字段（如 `this.setData({'product.images': ...})`），避免整体对象替换 |

### 12.3 分页防护

```python
# product_service.py
size = min(size, 100)  # 强制上限
```

后端强制限制单次查询最大条数为 100，防止恶意构造超大分页请求导致数据库 OOM。

### 12.4 浏览计数原子更新

使用数据库级别的原子操作更新浏览计数：
```sql
UPDATE products SET view_count = view_count + 1 WHERE id = ?
```
而非先 SELECT 再 UPDATE，消除并发竞争条件（Race Condition）。
