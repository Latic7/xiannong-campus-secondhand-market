# 后端 B 幂等与冲突测试记录

## 自动化测试

执行命令：

```powershell
conda run -n xiannong python -m unittest discover -s app/tests -v
```

后端 B 相关测试共 12 条，覆盖以下行为：

| 行为 | 预期结果 |
| --- | --- |
| 两个买家竞争同一个商品 | 仅一个订单创建成功，另一个返回 `409` |
| 同一商品重复下单 | 返回 `409`，不产生第二个有效订单 |
| 重复卖家确认 | 返回相同 `confirmed` 成功结果 |
| 重复取消 | 返回相同 `cancelled` 成功结果 |
| 重复完成 | 返回相同 `completed` 成功结果 |
| 重复评价 | 返回 `409`，数据库只保留一条评价 |
| 非卖家确认订单 | 返回 `403` |
| 非买家完成或评价 | 返回 `403` |
| 有效订单期间改价或下架 | 返回 `409` |
| 评价未完成订单 | 返回 `409` |
| 非法图片类型、空文件 | 返回 `400` |

## 并发保护

- 同进程请求使用商品维度互斥锁，防止双击或同一进程内并发重复提交。
- MySQL 请求在创建订单时通过 `SELECT ... FOR UPDATE` 锁定商品行。
- 锁内再次查询商品有效订单，保证竞争请求最多只有一个成功。

## MySQL 烟测

在 MySQL `8.0.42` 的 `test_xiannong` 中完成以下真实持久化流程：

1. 创建临时已发布商品。
2. 买家创建订单，状态为 `reserved`。
3. 卖家确认订单，状态为 `confirmed`。
4. 买家完成订单，订单为 `completed`，商品为 `sold`。
5. 买家提交评价。
6. 重新读取商品、订单和评价确认持久化。
7. 清理临时数据，并确认残留商品数为 `0`。

烟测结果：`MYSQL_SMOKE_OK`。

真实 MySQL 并发下单测试同时发起两个买家请求，结果为：

```text
MYSQL_CONCURRENCY_OK outcomes=[('created', 5004), ('conflict', None)]
```

数据库复查确认只产生一个有效订单，临时并发测试商品清理后残留数为 `0`。
