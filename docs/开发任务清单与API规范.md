# 校园二手交易平台开发任务清单与 API 规范

本文档根据 [team_docs/概要设计v1.4.html](../team_docs/概要设计v1.4.html) 和现有接口草案 [docs/api/openapi-draft.yaml](api/openapi-draft.yaml) 整理，目标是把概要设计落到可执行的开发任务、接口契约和验收标准上。

## 1. 项目目标

本项目是面向高校在校学生的微信小程序二手交易平台，采用“微信小程序前端 + FastAPI 后端 + MySQL 持久化”的分层架构，围绕以下主链路展开：

1. 微信授权登录与注册。
2. 商品浏览、搜索、详情查看、收藏。
3. 商品发布、编辑、上下架、图片管理与审核。
4. 发起交易、卖家确认、完成/取消、评价与信誉联动。
5. 举报、投诉、申诉、管理员处理。
6. 平台统计、日志、后台运维。

## 2. 交付物总清单

### 2.1 前端交付物

- 首页、列表页、详情页、发布页、用户中心页。
- 商品卡片组件与通用空状态、加载状态、错误提示组件。
- 登录态管理、接口封装、缓存封装。
- 图片上传、收藏、下单、举报、评价等交互流程。

### 2.2 后端交付物

- FastAPI 路由与控制器，按模块拆分为认证、用户、商品、订单、举报、管理后台。
- 数据库表结构、迁移脚本、初始化数据。
- JWT 鉴权、角色权限校验、统一响应、统一错误码。
- 审核、交易状态机、举报处理、统计聚合与日志。

### 2.3 文档与测试交付物

- OpenAPI 草案同步更新。
- Mock 示例同步更新。
- 单元测试、接口测试、关键链路集成测试。
- 部署说明、环境变量说明、回滚说明。

## 3. 任务拆解

### 3.1 前端任务清单

#### A. 通用基础能力

- 完成小程序全局配置、路由、主题样式和基础布局。
- 封装 `utils/api.js`，统一处理 baseURL、请求头、Token 注入、错误提示、重试和超时。
- 封装 `utils/storage.js`，统一管理 token、用户信息、草稿数据和缓存失效。
- 定义统一的页面状态：加载中、空数据、错误、无权限、登录过期。

#### B. 首页与列表页

- 首页展示推荐商品、最新商品、分类入口、搜索入口。
- 列表页支持分页、关键词搜索、分类筛选、排序、下拉刷新、上拉加载更多。
- 商品卡片组件展示标题、价格、成色/描述摘要、封面图、状态标签。

#### C. 商品详情页

- 展示商品详情、图片轮播、卖家信息、收藏、举报、联系、下单入口。
- 根据商品状态控制按钮可用性，例如已下架或已售出时禁用购买。
- 展示评价、订单状态和风险提示。

#### D. 发布页

- 表单字段：标题、描述、价格、分类、图片、联系方式/备注。
- 实现图片选择、预览、删除、上传前校验、上传后回填 URL。
- 提交前做前端校验，避免空标题、非法价格、超限图片等问题。

#### E. 用户中心页

- 实现微信登录、个人资料查看与编辑、我的发布、我的收藏、我的订单、我的举报。
- 提供退出登录、登录过期提示、身份刷新。
- 管理收藏关系与个人信誉信息展示。

#### F. 管理入口页面

- 预留管理员登录后的后台入口。
- 支持待审核商品、举报队列、用户状态管理、统计总览的基础页面。

### 3.2 后端任务清单

#### A. 接口基础设施

- 建立 FastAPI 项目入口、路由注册、依赖注入和异常处理。
- 统一响应结构为 `code / message / data / requestId / timestamp`。
- 统一错误码体系，区分认证、用户、商品、订单、举报、后台管理类错误。
- 实现日志记录、请求追踪 ID、参数校验、权限校验。

#### B. 账号与认证模块

- 接入微信登录，完成 `code` 换取登录态。
- 签发 access token 和 refresh token。
- 实现登录、刷新、注销、当前用户信息查询。
- 支持用户首次登录自动注册。

#### C. 用户与管理模块

- 实现个人资料读取与修改。
- 实现收藏列表、收藏新增、收藏删除。
- 实现用户状态管理，包括正常、封禁、解封。
- 实现信誉分查询与维护。

#### D. 商品与审核模块

- 实现商品发布、编辑、下架、删除、详情查询、列表检索。
- 实现商品图片上传和删除。
- 实现待审核商品队列、审核结果提交、审核记录留痕。
- 商品状态必须受审核流程和交易流程约束。

#### E. 交易与评价模块

- 实现订单创建、卖家确认、订单取消、订单完成、订单详情查询。
- 实现评价提交和信誉联动。
- 实现订单状态机和超时处理。
- 保证并发下单、重复操作和状态回退的幂等性。

#### F. 举报与投诉模块

- 实现举报提交、举报详情、举报处理进度查询。
- 实现管理员举报队列、处理动作、申诉入口。
- 实现处理结果通知和日志留存。

#### G. 统计与运维模块

- 实现平台总览指标、商品统计、交易统计、用户统计、管理员日志查询。
- 预留报表导出、聚合任务和慢查询分析。
- 记录关键操作日志，便于追踪审核和封禁行为。

## 4. 数据库设计任务

### 4.1 核心实体

- 用户 `users` / `user_profile`
- 管理员操作日志 `admin_logs`
- 商品 `products`
- 商品图片 `product_images`
- 商品分类 `categories`
- 订单 `orders`
- 收藏 `favorites`
- 评价 `reviews`
- 举报 `reports`
- 统计结果表 `stats_*`

### 4.2 关键设计要求

- 用户表必须对微信唯一标识建立唯一索引。
- 商品表必须对状态、创建时间、发布者建立常用索引。
- 订单表必须支持按买家、卖家、商品和状态查询。
- 举报表必须支持按状态、目标类型和处理人查询。
- 管理日志必须记录操作者、目标对象、动作、备注和时间。

### 4.3 状态机要求

- 商品状态：`draft -> pending -> published -> removed`，补充 `sold` 作为交易完成后的结果态。
- 订单状态：`created -> reserved -> confirmed -> completed | cancelled`。
- 举报状态：`open -> rejected | handled`。
- 用户状态：`active | banned`。

## 5. API 规范

### 5.1 全局约定

- 基础路径统一为 `/api`。
- 认证统一使用 `Bearer JWT`。
- 接口返回统一采用 JSON。
- 列表接口统一支持分页参数 `page`、`size`，按需支持 `keyword`、`sort`、`categoryId`。
- 时间字段统一使用 ISO 8601。
- 所有需要鉴权的接口都必须在后端校验 token 和角色权限。

### 5.2 通用响应结构

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "req-xxxx",
  "timestamp": "2026-05-14T08:00:00Z"
}
```

### 5.3 认证接口

| 接口 | 方法 | 用途 | 权限 |
| --- | --- | --- | --- |
| `/api/auth/wx-login` | POST | 微信授权登录并签发令牌 | 公开 |
| `/api/auth/refresh` | POST | 刷新 access token | 公开或带刷新令牌 |
| `/api/auth/logout` | POST | 注销登录态 | 已登录 |
| `/api/auth/me` | GET | 获取当前登录用户 | 已登录 |

请求示例：

```json
{
  "code": "wx-code-demo",
  "clientId": "mini-program"
}
```

返回数据建议包含：

- `accessToken`
- `refreshToken`
- `expiresIn`
- `user`

### 5.4 用户与管理接口

| 接口 | 方法 | 用途 | 权限 |
| --- | --- | --- | --- |
| `/api/users/me` | GET | 查询个人资料、信誉与状态 | 已登录 |
| `/api/users/me` | PUT | 更新个人资料 | 已登录 |
| `/api/users/me/favorites` | GET | 查询收藏列表 | 已登录 |
| `/api/users/me/favorites/{productId}` | POST | 新增收藏 | 已登录 |
| `/api/users/me/favorites/{productId}` | DELETE | 取消收藏 | 已登录 |
| `/api/admin/users` | GET | 管理员分页查询用户 | 管理员 |
| `/api/admin/users/{userId}/status` | PATCH | 管理员封禁或解封用户 | 管理员 |

### 5.5 商品与审核接口

| 接口 | 方法 | 用途 | 权限 |
| --- | --- | --- | --- |
| `/api/products` | GET | 商品列表检索 | 已登录或公开浏览 |
| `/api/products` | POST | 发布商品 | 已登录 |
| `/api/products/{productId}` | GET | 商品详情 | 公开或已登录 |
| `/api/products/{productId}` | PUT | 编辑商品 | 商品所有者或管理员 |
| `/api/products/{productId}` | DELETE | 下架或删除商品 | 商品所有者或管理员 |
| `/api/products/{productId}/images` | POST | 上传商品图片 | 商品所有者或管理员 |
| `/api/products/{productId}/images/{imageId}` | DELETE | 删除商品图片 | 商品所有者或管理员 |
| `/api/admin/products/pending` | GET | 获取待审核商品 | 管理员 |
| `/api/admin/products/{productId}/review` | POST | 提交审核结果 | 管理员 |

请求字段建议：

- 发布商品：`title`、`description`、`price`、`categoryId`、`images`
- 审核结果：`result`、`reason`

### 5.6 交易与评价接口

| 接口 | 方法 | 用途 | 权限 |
| --- | --- | --- | --- |
| `/api/orders` | POST | 买家发起交易请求 | 已登录 |
| `/api/orders/{orderId}` | GET | 查询订单详情 | 买家、卖家、管理员 |
| `/api/orders/{orderId}/seller-confirm` | POST | 卖家确认交易 | 卖家 |
| `/api/orders/{orderId}/cancel` | POST | 取消交易 | 买家、卖家、管理员 |
| `/api/orders/{orderId}/complete` | POST | 确认交易完成 | 买家、卖家 |
| `/api/orders/{orderId}/reviews` | POST | 提交交易评价 | 交易参与人 |

请求字段建议：

- 创建订单：`productId`、`remark`
- 评价：`score`、`content`

### 5.7 举报与投诉接口

| 接口 | 方法 | 用途 | 权限 |
| --- | --- | --- | --- |
| `/api/reports` | POST | 用户提交举报 | 已登录 |
| `/api/reports/{reportId}` | GET | 查询举报处理状态 | 已登录 |
| `/api/appeals` | POST | 提交申诉 | 已登录 |
| `/api/admin/reports` | GET | 管理员查询举报队列 | 管理员 |
| `/api/admin/reports/{reportId}/handle` | POST | 管理员处理举报 | 管理员 |

处理动作建议支持：

- `reject`
- `warning`
- `unlist_product`
- `ban_user`

### 5.8 统计与运维接口

| 接口 | 方法 | 用途 | 权限 |
| --- | --- | --- | --- |
| `/api/admin/stats/overview` | GET | 平台运营总览 | 管理员 |
| `/api/admin/stats/products` | GET | 商品统计 | 管理员 |
| `/api/admin/stats/trades` | GET | 交易统计 | 管理员 |
| `/api/admin/stats/users` | GET | 用户活跃与信誉统计 | 管理员 |
| `/api/admin/logs` | GET | 管理员操作日志 | 管理员 |

## 6. 开发里程碑

### 阶段一：基础骨架

- 完成商品发布、浏览、详情、收藏。

### 阶段三：治理能力

- 完成举报、申诉、审核、封禁和后台处理。
- 完成操作日志和统计接口。

### 阶段四：质量收尾

- 完成测试、联调、性能检查、文档整理和部署说明。

## 7. 验收标准

- 能完成微信登录并拿到可用 token。
- 能浏览、搜索、发布、编辑、下架商品。
- 能创建订单、确认订单、完成订单并提交评价。
- 能提交举报并由管理员处理。
- 能在后台查看统计和日志。
- 所有核心接口均有请求示例、响应示例和错误码说明。

## 9. 团队分工与第一步任务

下面按“先能跑通主链路，再逐步补齐治理能力”的方式拆分第一步任务。每个人先交付一个最小可验证结果，避免一开始就铺太大。

### 9.1 前端 1：主页与列表

- 负责范围：`pages/home`、`pages/list`、`components/item-card`、`utils/api.js` 的列表接口接入。
- 第一步任务：把首页和列表页做成“能从接口拿到数据并渲染”的状态，至少完成商品列表展示、空状态和加载状态。
- 第一阶段交付：能调用 `GET /api/products`，把返回的商品卡片渲染出来，并支持分页参数的传递。

### 9.2 前端 2：详情、发布与个人中心

- 负责范围：`pages/detail`、`pages/post`、`pages/user`、`utils/storage.js` 的登录态读写。
- 第一步任务：先把详情页和个人中心页接入数据读取，再把发布页的表单结构和基础校验搭起来。
- 第一阶段交付：能调用 `GET /api/products/{productId}` 和 `GET /api/users/me`，并完成发布页字段、图片占位和表单提交流程的前置准备。

### 9.3 后端 1：认证与用户

- 负责范围：`/api/auth/*`、`/api/users/*`。
- 第一步任务：把登录、刷新、当前用户信息这条链路先做实，补齐统一响应、token 结构和用户资料返回。
- 第一阶段交付：`POST /api/auth/wx-login`、`POST /api/auth/refresh`、`GET /api/auth/me`、`GET /api/users/me` 能返回符合 OpenAPI 的字段级结果。

### 9.4 后端 2：商品与交易

- 负责范围：`/api/products/*`、`/api/orders/*`。
- 第一步任务：先把商品列表、商品详情、商品发布和订单创建做成可联调的最小闭环。
- 第一阶段交付：`GET /api/products`、`POST /api/products`、`GET /api/products/{productId}`、`POST /api/orders` 能返回明确的字段，并且返回结构与 OpenAPI 对齐。

### 9.5 后端 3：举报、后台与统计

- 负责范围：`/api/reports/*`、`/api/admin/*`。
- 第一步任务：先把举报提交、举报查询和后台统计总览做起来，再补管理员处理动作。
- 第一阶段交付：`POST /api/reports`、`GET /api/reports/{reportId}`、`GET /api/admin/stats/overview` 可用，并输出稳定的字段结构。

### 9.6 测试同学：契约测试与联调清单

- 负责范围：接口契约、测试用例、联调验证、回归检查。
- 第一步任务：先把 OpenAPI 里的主链路整理成测试清单，定义哪些接口属于登录、商品、交易、举报四条主线。
- 第一阶段交付：输出一份最小联调清单，覆盖 `auth -> users -> products -> orders -> reports` 的成功路径和常见失败路径。
- 备注：如果暂时不设独立测试岗位，这位同学可以优先协助后端 3 的接口契约整理，或者协助前端 2 做页面联调验证。

### 9.7 推荐的推进顺序

1. 先打通认证与用户信息。
2. 再打通商品列表与详情。
3. 然后做商品发布和订单创建。
4. 最后补举报、后台和统计。

这样分配的好处是，前 1 周就能看到首页、列表、详情和登录态这条主线在跑，后面再逐步补后台治理功能。
