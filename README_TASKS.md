项目框架与任务拆分（占位，供组长分配）

- **前端页面**
  - `pages/home`：首页，显示推荐/最新
  - `pages/list`：商品列表，支持筛选/分页
  - `pages/detail`：商品详情，联系/下单/收藏
  - `pages/post`：发布商品，表单与图片上传
  - `pages/user`：用户中心，登录/我的发布

- **组件**
  - `components/item-card`：商品卡片

- **工具/服务**
  - `utils/api.js`：与后端交互封装
  - `utils/storage.js`：本地存储封装

建议把每个条目拆成 1-2 天的小任务，分别分配给组员，并在 PR 合并后删除临时分支。

## 后端任务（FastAPI）

项目后端采用 FastAPI，已在概要设计中将后端拆分为六个核心模块（账号与认证、用户与管理、商品与审核、交易与评价、举报与投诉、统计与运维）。建议按下面分工给 3 人负责：

- 后端 A（认证 + 用户）：
  - 负责 `账号与认证`、`用户与管理` 模块的接口实现与 DB 设计（`users`, `user_profile`, `favorites`），实现 JWT 登录/刷新、`/api/users/me` 等接口，编写单元测试与接口示例。
  - 交付物：OpenAPI 文档（YAML/JSON）、用户模块单元测试、迁移脚本。

- 后端 B（商品 + 交易）：
  - 负责 `商品与审核`、`交易与评价` 模块（`products`, `product_images`, `orders`, `reviews`），实现商品发布/图片上传接口、订单状态机、并发控制与补偿逻辑。
  - 交付物：商品/订单接口实现、图片上传集成说明、端到端测试用例。

- 后端 C（治理 + 运维）：
  - 负责 `举报与投诉`、`统计与运维` 与管理员后台接口（`reports`, `admin_logs`, 统计聚合表），实现管理员审查接口、报表接口与操作日志，并搭建基础监控/日志采集点。
  - 交付物：管理员 API、统计聚合脚本、监控/日志说明。

公共任务（每人协作）
- API 约定与错误码表（由一人主导维护，产出 OpenAPI）
- 数据库迁移与基本种子数据
- CI（单元测试）、Dockerfile、部署脚本
- OpenAPI 草稿位置：`docs/api/openapi-draft.yaml`（前后端联调统一以此为准，变更需走 PR）
- Mock 响应示例：`docs/api/mock-examples.yaml`（前端可先据此开发页面与状态流转）

任务分配建议（2 前端，3 后端）
- 前端 1：负责 `pages/home`、`pages/list`、`components/item-card`（UI + 列表接口对接）
- 前端 2：负责 `pages/detail`、`pages/post`、`pages/user`（表单、图片上传、用户中心）
- 后端 1/2/3：分别按上文 A/B/C 分工，各自负责对应模块的接口、数据库与测试。

开发与部署说明（前后端关系）
- 微信小程序：前端是运行在微信客户端的代码包（WXML/JS/WXSS），需要打包上传到微信小程序平台；它只包含前端页面与少量客户端逻辑。
- FastAPI 后端：独立部署为 HTTP 服务（云服务器或云函数），接收前端的 HTTPS/JSON 请求，负责鉴权、业务逻辑与数据持久化。
- 并行开发建议：前后端应并行开发，双方先约定接口契约（OpenAPI/Mock），前端可基于 Mock Server 开发 UI，后端实现真实接口并通过 CI 验证兼容性。
- 发布说明：最终部署时，前端包（小程序代码）上传到微信平台；后端服务打包部署到云端。两者独立发布，但必须保证接口版本兼容。
